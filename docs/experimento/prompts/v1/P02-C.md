Você é um desenvolvedor backend Java. Sua função é desenvolver apenas as funcionalidades descritas neste prompt.

Funcionalidade: Autenticação e autorização por perfis

Como usuário do sistema
Quero autenticar-me com e-mail e senha
Para acessar somente as operações permitidas pelo meu perfil

Contexto:
Dado que a aplicação utiliza Java 21, Spring Boot 4.1.1, Maven, PostgreSQL e Flyway
E a classe principal da aplicação é "devheloisacabral.tcc.com.esportiva.EsportivaApplication"
E existe a tabela "users" criada pela migration anterior
E os perfis válidos são somente "admin", "professor" e "aluno"
E a senha persistida deve permanecer na coluna "password_hash"
E a chave privada RSA deve ser fornecida exclusivamente por configuração externa
E a chave RSA utilizada deve possuir no mínimo 2048 bits
E somente os cenários deste prompt estão autorizados para implementação

Regras e cenários:

- Usuários dos perfis admin, professor e aluno devem conseguir autenticar com credenciais válidas, recebendo access token e refresh token.
- Os tokens devem usar RS256; o access token deve expirar em 15 minutos e o refresh token em 7 dias.
- Credenciais inválidas devem retornar HTTP 401 sem emitir tokens nem expor detalhes internos.
- Senhas devem ser verificadas e persistidas somente como hash BCrypt; nenhum log pode registrar a senha.
- Operações protegidas sem access token devem retornar HTTP 401.
- GET /auth/me deve retornar somente identificação, e-mail e perfil do usuário autenticado.
- Operação exclusiva de admin deve permitir admin e retornar HTTP 403 para professor e aluno.
- POST /auth/refresh deve rotacionar refresh tokens válidos, invalidar o anterior e rejeitar tokens inválidos, expirados, revogados ou reutilizados.
- POST /auth/logout deve revogar o refresh token informado e impedir nova renovação.
- GET /health deve continuar público e retornar HTTP 200 com status "operational".

Restrições:

- Preservar a migration e o contrato da tabela users.
- Criar nova migration para refresh tokens.
- Persistir somente o hash SHA-256 dos refresh tokens.
- Não persistir a chave privada RSA, senhas em texto puro ou tokens em texto puro.
- Não implementar funcionalidades de prompts futuros.
