Você é um desenvolvedor backend Java. Sua função é desenvolver apenas as funcionalidades descritas neste prompt.

Funcionalidade: Cadastro e consulta de alunos

Como administrador da Esportiva
Quero cadastrar e consultar alunos
Para manter os dados cadastrais protegidos e controlados por autorização

Contexto:
Dado que a API utiliza Java 21, Spring Boot, Maven, PostgreSQL e Flyway
E existe autenticação implementada conforme o Prompt 2
E existem os perfis "admin", "professor" e "aluno"
E o usuário autenticado possui um access token válido
E o banco de dados está disponível para a aplicação
E somente os cenários deste prompt estão autorizados para implementação

Regras de cadastro:

- Somente o perfil `admin` pode cadastrar alunos.
- O cadastro deve receber nome, e-mail, telefone, data de nascimento e senha.
- Todo aluno novo deve ser criado automaticamente com status `inativo`.
- O status não pode ser informado nem controlado pelo cliente.
- A senha deve ser persistida somente como representação protegida e nunca retornada ou registrada em logs.
- O e-mail deve ser único e essa unicidade deve ser protegida também no banco de dados.
- Dados obrigatórios ausentes ou inválidos devem gerar erro de validação sem criar aluno.
- Requisições sem autenticação devem retornar HTTP 401.
- Requisições de professor ou aluno para cadastro devem retornar HTTP 403.

Regras de consulta:

- Admin pode consultar os alunos e recebe os dados cadastrais permitidos e o status.
- Professor somente pode consultar alunos quando houver relação autorizada pelas regras já existentes; não pode haver acesso indiscriminado.
- Aluno somente pode consultar o próprio cadastro.
- A senha nunca pode ser retornada.

Endpoints autorizados neste incremento:

- `POST /alunos`
- `GET /alunos`

Não implementar planos, mensalidades, ativação por pagamento, matrículas, turmas, aulas, presenças, frontend ou qualquer funcionalidade de prompts futuros.
