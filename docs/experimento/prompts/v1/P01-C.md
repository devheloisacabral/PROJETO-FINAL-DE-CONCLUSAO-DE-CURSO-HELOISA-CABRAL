@prompt-01 @fundacao @api-rest @java @spring-boot @postgresql @bdd

Você é um desenvolvedor backend Java. Sua função é desenvolver apenas as funcionalidades descritas neste prompt.

Funcionalidade: Fundação técnica executável da API de gestão de aulas

Como equipe de desenvolvimento
Quero estabelecer a fundação técnica, arquitetural e de persistência da aplicação
Para que os próximos incrementos sejam implementados de forma incremental,
testável, rastreável e conforme o PGP.

Contexto:
Dado que o sistema será uma API REST backend
E que a linguagem definida é Java 21 LTS
E que o framework definido é Spring Boot
E que o projeto utilizará Maven
E que o banco de dados definido é PostgreSQL
E que as alterações estruturais do banco serão controladas por Flyway
E que a classe principal da aplicação é
"devheloisacabral.tcc.com.esportiva.EsportivaApplication"
E que somente os cenários deste prompt estão autorizados para implementação

Cenário: Criar a estrutura inicial do projeto

    Quando a estrutura inicial do projeto for criada
    Então deve existir um arquivo de configuração Maven
    E deve existir Maven Wrapper
    E o projeto deve utilizar Java 21
    E a versão do Spring Boot deve estar explicitamente definida
    E deve existir uma classe executável
      "devheloisacabral.tcc.com.esportiva.EsportivaApplication"
    E a estrutura deve separar responsabilidades de domínio, aplicação, persistência e apresentação

Cenário: Utilizar somente dependências necessárias

    Quando as dependências do projeto forem configuradas
    Então devem ser utilizadas as dependências necessárias para API REST
    E devem ser utilizadas as dependências necessárias para validação
    E devem ser utilizadas as dependências necessárias para JPA e Hibernate
    E deve ser utilizado o driver JDBC do PostgreSQL
    E deve ser utilizada a dependência do Flyway
    E nenhuma dependência adicional deve ser incluída sem necessidade técnica comprovada

Cenário: Configurar a conexão com PostgreSQL

    Dado que existe uma instância local do PostgreSQL disponível
    Quando a configuração da aplicação for criada
    Então a URL do banco deve ser obtida pela variável de ambiente "DB_URL"
    E o usuário do banco deve ser obtido pela variável de ambiente "DB_USERNAME"
    E a senha do banco deve ser obtida pela variável de ambiente "DB_PASSWORD"
    E a variável "DB_URL" deve iniciar com "jdbc:postgresql://"
    E a URL não deve utilizar somente o formato "postgresql://"
    E a URL não deve conter credenciais incorporadas quando usuário e senha forem fornecidos separadamente

Cenário: Executar a aplicação com configuração válida

    Dado que o PostgreSQL local está em execução
    E que "DB_URL" possui o formato "jdbc:postgresql://host:porta/banco"
    E que "DB_USERNAME" está configurada
    E que "DB_PASSWORD" está configurada
    Quando a aplicação for executada pela classe
      "devheloisacabral.tcc.com.esportiva.EsportivaApplication"
    Então o Spring Boot deve iniciar
    E o servidor HTTP deve ficar disponível na porta 8081
    E a aplicação deve iniciar sem erros

Cenário: Configurar o Flyway

    Dado que o PostgreSQL local está disponível
    Quando a aplicação for iniciada
    Então o Flyway deve ser executado automaticamente
    E as migrations devem estar organizadas em arquivos versionados
    E as migrations devem ser aplicadas sem intervenção manual
    E o histórico das migrations deve ser registrado no PostgreSQL
    E uma migration já aplicada não deve ser executada novamente
    E alterações futuras de estrutura devem utilizar novas migrations
    E o Hibernate não deve criar ou alterar tabelas automaticamente

Cenário: Criar a estrutura inicial de autenticação

    Dado que os perfis definidos no PGP são "admin", "professor" e "aluno"
    Quando a migration inicial de usuários for executada
    Então deve existir uma tabela para representar usuários de autenticação
    E cada usuário deve possuir e-mail
    E cada usuário deve possuir senha armazenada de forma protegida
    E cada usuário deve possuir um perfil
    E o e-mail deve possuir unicidade em todo o sistema
    E os perfis permitidos devem ser "admin", "professor" e "aluno"
    E não deve existir uma coluna de senha em texto puro
    E o fluxo de login não deve ser implementado neste prompt
    E access tokens não devem ser implementados neste prompt
    E refresh tokens não devem ser implementados neste prompt

Cenário: Disponibilizar o endpoint de saúde da API

    Dado que a aplicação foi iniciada corretamente
    Quando for realizada uma requisição HTTP GET para "/health"
    Então a API deve responder com HTTP 200
    E a resposta deve indicar que a aplicação está operacional
    E o endpoint não deve exigir autenticação
    E o endpoint não deve depender de funcionalidades dos prompts seguintes
