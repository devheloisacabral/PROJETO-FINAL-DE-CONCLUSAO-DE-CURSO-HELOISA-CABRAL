@prompt-05 @professores @admin @autorizacao @bdd

Você é um desenvolvedor backend Java. Implemente exclusivamente os cenários de professores deste incremento.

Funcionalidade: Cadastro e gestão de professores

Contexto:

- A fundação, autenticação/perfis, cadastro de alunos e planos/mensalidades dos Prompts 1 a 4 existem.
- Os perfis são `admin`, `professor` e `aluno`.
- Somente `admin` pode executar operações administrativas de professores.
- Professores são usuários autenticáveis com o papel `professor`.
- A API utiliza Java 21, Spring Boot, Maven, PostgreSQL, Flyway e autenticação existente.

Regras autorizadas:

- Admin pode cadastrar professor com nome, e-mail, data de nascimento, CREF e senha válidos.
- Nome, e-mail, data de nascimento, CREF e senha são obrigatórios; e-mail deve possuir formato válido e data de nascimento deve estar no passado.
- O e-mail deve ser normalizado e permanecer único em todo o sistema.
- O CREF deve ser obrigatório, único e persistido.
- A senha deve ser armazenada somente de forma protegida, sem exposição nas respostas ou consultas.
- O usuário criado deve possuir o papel `professor` e o professor deve iniciar com status `ativo`.
- Admin pode listar professores e consultar um professor por identificador, sem retornar senha, hash ou credenciais.
- Admin pode atualizar os dados cadastrais e o CREF sem alterar indevidamente o papel ou a senha existente.
- Admin pode inativar e reativar professor.
- Admin pode excluir professor.
- Operações de gestão de professores devem ser negadas para professor e aluno.
- Criar uma nova migration sem alterar migrations já aplicadas, preservando unicidade, chave estrangeira e os status `ativo` e `inativo`.

Endpoints autorizados:

- `POST /professores`
- `GET /professores`
- `GET /professores/{id}`
- `PUT /professores/{id}`
- `PATCH /professores/{id}/inativar`
- `PATCH /professores/{id}/reativar`
- `DELETE /professores/{id}`

Não implementar folha de pagamento, agenda, turmas, aulas, presenças, permissões adicionais, histórico de alterações, frontend ou funcionalidades de prompts futuros.
