@prompt-04 @planos @mensalidades @admin @aluno @bdd

Você é um desenvolvedor backend Java. Implemente exclusivamente os cenários de planos e mensalidades deste incremento.

Funcionalidade: Planos e mensalidades

Contexto:

- A fundação, autenticação/perfis e cadastro de alunos dos Prompts 1, 2 e 3 existem.
- Os perfis são `admin`, `professor` e `aluno`.
- Somente `admin` pode executar operações administrativas.
- Aluno novo inicia com status `inativo`.
- A API utiliza Java 21, Spring Boot, Maven, PostgreSQL, Flyway e autenticação existente.

Regras autorizadas:

- Admin pode criar plano com nome e valor válidos.
- Nome e valor são obrigatórios e devem ser validados.
- Admin pode associar um único plano ao aluno; nova associação substitui a anterior sem criar histórico financeiro.
- Admin pode criar mensalidade para aluno com plano associado.
- A mensalidade deve iniciar como `pendente`, usar o valor do plano e vencer no dia 10 do mês de referência.
- Deve existir no máximo uma mensalidade por aluno e mês de referência.
- Mensalidade sem plano associado não pode ser criada.
- Receber mensalidade `pendente` altera para `paga` e ativa aluno `inativo` na mesma operação; aluno já `ativo` permanece ativo.
- Receber mensalidade `paga` é impedido.
- Cancelar recebimento somente de mensalidade `paga` retorna para `pendente`; não persistir status `cancelada`.
- Admin consulta mensalidades administrativas; aluno consulta somente as próprias; professor não consulta dados financeiros.
- As operações administrativas são negadas para professor e aluno.
- Criar migrations novas sem alterar migrations já aplicadas, preservando integridade referencial e unicidade aluno+mês.

Endpoints autorizados:

- `POST /planos`
- `PUT /alunos/{id}/plano`
- `POST /mensalidades`
- `PATCH /mensalidades/{id}/receber`
- `PATCH /mensalidades/{id}/cancelar`
- `GET /mensalidades`
- `GET /mensalidades/{id}`

Não implementar gateway de pagamento, histórico financeiro adicional, planos múltiplos por aluno, status `cancelada`, matrículas, turmas, aulas, presenças, dashboard, frontend ou funcionalidades de prompts futuros.
