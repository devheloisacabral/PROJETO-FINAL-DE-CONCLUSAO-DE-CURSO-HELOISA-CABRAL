# P17-C — Transferência de aluno entre turmas

## Contexto

A API possui turmas, matrículas e capacidade. O administrador poderá transferir um aluno de uma turma para outra, cancelando ou encerrando a matrícula anterior e criando a nova em uma única operação consistente.

## Objetivo

Implementar transferência entre turmas alterando regras de matrícula, capacidade, conflito de turma e histórico.

## Critérios BDD

Funcionalidade: Transferência entre turmas

### Cenário: Administrador transfere aluno para turma com vaga

Dado que o aluno possui matrícula ativa na turma A
E a turma B está ativa e possui vaga
Quando o administrador transfere o aluno da turma A para a turma B
Então a matrícula da turma A deve deixar de ser ativa
E deve existir matrícula ativa na turma B
E a capacidade ocupada das duas turmas deve refletir a transferência

### Cenário: Transferência falha quando turma destino está cheia

Dado que o aluno possui matrícula ativa na turma A
E a turma B está sem vagas
Quando o administrador tenta transferir o aluno para a turma B
Então a API deve bloquear a transferência
E a matrícula na turma A deve continuar ativa

### Cenário: Transferência falha quando origem não está ativa

Dado que a matrícula do aluno na turma A está cancelada
Quando o administrador tenta transferir o aluno para outra turma
Então a API deve bloquear a operação
E não deve criar nova matrícula

### Cenário: Sistema impede transferência para a mesma turma

Dado que o aluno possui matrícula ativa na turma A
Quando o administrador tenta transferir o aluno da turma A para a turma A
Então a API deve retornar erro de regra de negócio

### Cenário: Sistema impede duplicidade ativa no destino

Dado que o aluno já possui matrícula ativa na turma B
Quando o administrador tenta transferir o aluno para a turma B a partir de outra turma
Então a API deve bloquear a operação
E não deve encerrar a matrícula de origem

## Regras

- A transferência deve ser executada em uma única transação.
- Todas as validações devem ocorrer antes de alterar a matrícula de origem.
- A matrícula de origem deve ser cancelada sem exclusão do histórico.
- A matrícula destino deve ser criada como ativa.
- A capacidade deve considerar somente matrículas ativas.
- Não criar frontend, dependências novas ou funcionalidades fora desta manutenção.
