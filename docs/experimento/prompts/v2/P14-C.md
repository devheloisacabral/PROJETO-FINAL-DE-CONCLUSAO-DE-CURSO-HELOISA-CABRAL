# P14-C — Pagamento parcial de mensalidade

## Contexto

A API trata mensalidade como pendente ou paga, e o recebimento de uma mensalidade pendente altera seu status para paga. Agora será possível registrar pagamentos parciais, mudando a regra de quitação.

## Objetivo

Implementar pagamentos parciais para mensalidades, de modo que uma mensalidade só fique paga quando a soma dos pagamentos válidos atingir o valor cobrado.

## Critérios BDD

Funcionalidade: Pagamento parcial de mensalidade

### Cenário: Administrador registra pagamento parcial

Dado que existe mensalidade pendente no valor de 200.00
Quando o administrador registra pagamento de 80.00
Então a mensalidade deve continuar pendente
E o total pago deve ser 80.00

### Cenário: Mensalidade é quitada ao atingir o valor devido

Dado que existe mensalidade pendente no valor de 200.00
E já existe pagamento válido de 80.00
Quando o administrador registra pagamento de 120.00
Então a mensalidade deve ficar paga
E o total pago deve ser 200.00

### Cenário: Aluno inativo só é ativado quando a mensalidade é quitada

Dado que existe aluno inativo com mensalidade pendente de 200.00
Quando o administrador registra pagamento parcial de 100.00
Então o aluno deve continuar inativo
Quando o administrador registra o pagamento restante
Então a mensalidade deve ficar paga
E o aluno deve ficar ativo

### Cenário: Sistema bloqueia pagamento acima do saldo restante

Dado que existe mensalidade pendente de 200.00 com 150.00 já pagos
Quando o administrador tenta registrar pagamento de 60.00
Então a API deve bloquear a operação
E o total pago deve permanecer 150.00

### Cenário: Cancelamento de pagamento parcial recalcula status

Dado que existe mensalidade paga por dois pagamentos parciais
Quando o administrador cancela um dos pagamentos
Então a mensalidade deve voltar para pendente
E o total pago deve refletir apenas pagamentos válidos restantes

## Regras

- Cada pagamento deve ser persistido individualmente e iniciar como válido.
- O status da mensalidade deve ser calculado pela soma dos pagamentos válidos.
- Pagamento maior que o saldo restante deve ser bloqueado sem persistência.
- O aluno só deve ser ativado quando a mensalidade for quitada.
- Cancelamento deve preservar o registro e alterar somente seu status para cancelado.
- Não criar frontend, dependências novas ou funcionalidades fora desta manutenção.
