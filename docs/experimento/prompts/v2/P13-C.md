# P13-C — Troca de plano com vigência

## Contexto

A API já permite associar um plano ao aluno, substituindo a associação anterior sem histórico financeiro. A troca de plano deve ter vigência e preservar o valor histórico cobrado em mensalidades já criadas.

## Objetivo

Implementar troca de plano com data de início de vigência, alterando a regra existente de associação direta de plano ao aluno.

## Critérios BDD

Funcionalidade: Troca de plano com vigência

### Cenário: Administrador agenda troca de plano futura

Dado que um aluno possui o plano Básico vigente
E existe o plano Premium ativo
Quando o administrador agenda o plano Premium com início em 2026-11-01
Então o histórico do aluno deve registrar a nova vigência
E o plano vigente antes de 2026-11-01 deve continuar sendo o Básico

### Cenário: Mensalidade usa plano vigente no mês de referência

Dado que o aluno possui plano Básico vigente em 2026-10
E plano Premium vigente a partir de 2026-11-01
Quando o administrador cria a mensalidade de 2026-11
Então a mensalidade deve usar o valor do plano Premium

### Cenário: Mensalidade já criada preserva valor histórico

Dado que existe mensalidade de 2026-10 criada com valor do plano Básico
Quando o administrador agenda troca para plano Premium
Então a mensalidade de 2026-10 deve manter o valor original

### Cenário: Sistema bloqueia vigência sobreposta

Dado que existe uma troca de plano já vigente a partir de 2026-11-01
Quando o administrador tenta cadastrar outra troca com a mesma vigência para o mesmo aluno
Então a API deve bloquear a operação
E não deve criar histórico duplicado

### Cenário: Sistema bloqueia mensalidade quando não há plano vigente

Dado que um aluno não possui plano vigente no mês informado
Quando o administrador tenta criar a mensalidade desse mês
Então a API deve retornar erro de regra de negócio
E não deve criar mensalidade

## Regras

- A associação deve registrar aluno, plano e data inicial de vigência.
- A mensalidade deve consultar a associação mais recente cuja vigência seja anterior ou igual ao primeiro dia do mês de referência.
- O valor da mensalidade deve ser copiado no momento da criação e não recalculado por alterações futuras.
- A mesma data de início não pode ser cadastrada duas vezes para o mesmo aluno.
- Sem plano vigente no mês informado, a mensalidade não deve ser persistida.
- Não criar frontend, dependências novas ou funcionalidades fora desta manutenção.
