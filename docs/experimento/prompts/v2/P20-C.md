# P20-C — Reagendamento de aula e impacto em presenças e dashboard

## Contexto

A API já permite criar aulas com base na turma e listar próximas aulas no dashboard, incluindo indicador de cancelamento. Agora aulas poderão ser reagendadas, afetando horário, data, presença e dashboard.

## Objetivo

Implementar reagendamento de aula, alterando regras de aula, presença, conflito de horário e dashboard administrativo.

## Critérios BDD

### Cenário: Administrador reagenda aula futura sem presença registrada

Dado que existe uma aula futura não cancelada
E a aula não possui presenças registradas
Quando o administrador reagenda a aula para uma nova data e horário válidos
Então a aula deve ser atualizada
E o dashboard deve exibir a aula na nova data e horário

### Cenário: Sistema bloqueia reagendamento de aula cancelada

Dado que existe uma aula cancelada
Quando o administrador tenta reagendar essa aula
Então a API deve bloquear a operação
E a aula deve permanecer cancelada

### Cenário: Sistema bloqueia reagendamento quando já há presença

Dado que existe aula com presença registrada
Quando o administrador tenta reagendar a aula
Então a API deve bloquear a operação
E as presenças existentes devem ser preservadas

### Cenário: Sistema impede duplicidade de aula no mesmo horário

Dado que já existe aula para uma turma em 2026-10-05 das 09:00 às 10:00
Quando o administrador tenta reagendar outra aula da mesma turma para a mesma data e horário
Então a API deve bloquear a operação
E não deve criar ou atualizar registro duplicado

### Cenário: Dashboard reflete reagendamento

Dado que uma aula futura foi reagendada
Quando o administrador consulta o dashboard do mês correspondente
Então a lista de próximas aulas deve considerar a nova data e horário
E não deve exibir a data antiga da aula reagendada

## Regras técnicas

- Disponibilizar reagendamento administrativo em `PATCH /aulas/{id}/reagendar`.
- Aceitar data futura e horário com início anterior ao fim.
- Bloquear aula cancelada ou aula com qualquer presença registrada.
- Impedir sobreposição de horário com outra aula não cancelada da mesma turma, excluindo a própria aula.
- Preservar presenças existentes e atualizar a própria aula, sem criar novo registro.
- Não criar frontend, dependências novas, migration ou funcionalidades fora desta manutenção.
