# P19-C — Conflito de horários em turmas e matrículas

## Contexto

A API possui turmas com dia da semana, horário, professores associados e matrículas de alunos. O sistema deve impedir conflitos de horário para professores e alunos.

## Objetivo

Alterar as regras de criação e atualização de turmas e matrículas para impedir sobreposição de horários, preservando horários encostados e matrículas canceladas.

## Critérios BDD

### Cenário: Sistema bloqueia professor em turmas sobrepostas

Dado que um professor está associado a uma turma ativa na segunda-feira das 09:00 às 10:00
Quando o administrador tenta associar o professor a outra turma ativa na segunda-feira das 09:30 às 10:30
Então a API deve bloquear a operação

### Cenário: Sistema permite horários encostados para professor

Dado que um professor está associado a uma turma ativa das 09:00 às 10:00
Quando o administrador associa o professor a outra turma no mesmo dia das 10:00 às 11:00
Então a operação deve ser permitida

### Cenário: Sistema bloqueia aluno em matrículas sobrepostas

Dado que um aluno possui matrícula ativa em turma na terça-feira das 18:00 às 19:00
Quando o administrador tenta matricular o aluno em outra turma ativa na terça-feira das 18:30 às 19:30
Então a API deve bloquear a matrícula

### Cenário: Matrícula cancelada não gera conflito

Dado que o aluno possui matrícula cancelada em turma das 18:00 às 19:00
Quando o administrador matricula o aluno em turma ativa no mesmo horário
Então a matrícula deve ser permitida se houver vaga e demais regras forem atendidas

### Cenário: Atualização de horário da turma revalida conflitos existentes

Dado que existe uma turma com alunos e professores associados
Quando o administrador altera o horário da turma
Então a API deve validar conflitos para professores e alunos afetados
E deve bloquear a alteração se houver sobreposição

## Regras técnicas

- Considerar sobreposição quando o novo início for anterior ao fim existente e o novo fim for posterior ao início existente.
- Permitir intervalos que apenas encostam no limite, como 09:00–10:00 e 10:00–11:00.
- Considerar somente turmas ativas, professores associados ativos e matrículas ativas em turmas ativas.
- Não criar frontend, dependências novas, migration ou funcionalidades fora desta manutenção.
